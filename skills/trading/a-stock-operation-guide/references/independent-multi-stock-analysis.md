# 多股独立分析与来源披露工作流

适用于用户一次提交多只股票，并明确要求由当前主模型独立研判的场景。

## 路由原则

1. 默认由 Hermes 当前主模型分析，不调用 AGY/Antigravity。
2. 只有用户在当前请求中明确写出“用AGY分析”“让AGY审”“调用Antigravity”等指令时，才允许走 AGY 路径。
3. 不得依据历史偏好、旧会话或工具描述中的“首选”措辞自动启用 AGY。
4. 最终答复首部必须披露：`分析来源：Hermes 当前主模型独立研判，未调用 AGY。`

## 数据边界

- 非交易日分析“周一/下一交易日”时，先确认交易日状态，并将数据边界锁定到最近一个已完成交易日收盘。
- 每只股票至少获取：收盘行情、100根日线、100根30分钟K线、资金流、筹码分布、技术指标、最新公告/新闻。
- 关键价格、涨跌幅与高低点应以权威实时行情和K线数据交叉核验。
- 新闻无有效结果时明确写“未检索到有效近期公司级催化”，不得用泛行业新闻替代公司事实。

## 批处理方式

- 股票较多时按2—3只分组并行采集，避免串行调用造成超时。
- 子任务只负责采集和结构化初判；主模型必须统一校验结论、排序和风险口径。
- 禁止子任务调用 `analyze_stock_with_antigravity` 或相关脚本，除非用户明确要求AGY。
- 子任务结果属于工作材料，最终结论仍标注为 Hermes 综合研判，不把子任务冒充外部模型。

## 单股最小分析结构

1. 数据日期与收盘状态。
2. 趋势：MA5/10/20/60、MACD、量价。
3. 资金与筹码：当日及5/20日主力、平均成本、获利盘、集中度。
4. 缠论：走势类型、中枢位置、背驰状态、当前买卖点分类。
5. 下一交易日三情景：偏强、中性、偏弱。
6. 操作：持仓与空仓分别说明，使用结构触发条件，不用固定价格冒充确定性买卖点。
7. 红线：中枢破坏、反抽失败、资金背离、重大公告风险。

## 推演对照裁决

当用户要求“独立分析后判断是否同意另一份推演”时，不要直接复述对方观点。按以下顺序：

1. 先恢复原推演的核心命题：强弱排序、趋势定性、关键压力/支撑、入场方式和失效条件。
2. 在不引用其结论的情况下完成独立拉数与判断。
3. 每只股票分别输出：`同意部分 / 不同意部分 / 修正后的路径 / 交易红线`。
4. 把“突破尝试”“尾盘脉冲”“技术反抽”“主升确认”严格区分：单日上涨或尾盘急拉不能单独证明主升。
5. 若大盘健康度处于熔断区，个股相对强势只能提高观察优先级，不能自动转化为抄底许可。
6. 关键价位须来自前高、当日高低、均线、筹码成本或波动结构，并说明价位对应的动作；不要只给“看多/看空”。
7. 多股最终必须给唯一强弱排序，同时说明“强于另一只”不等于“现在可以买”。

### 尾盘脉冲验证

若主要涨幅集中于最后1—2根30分钟K线：

- 对照全天主力净流入、5日资金、成交额与收盘距最高点回撤；
- 次日需验证前高突破后站稳、回踩承接和板块共振；
- 获利盘比例、RSI2或BIAS极高时，禁止把尾盘急拉直接定义为趋势主升；
- 输出应优先写“等待验证/突破确认”，而非追涨。

## 多股汇总

按以下三类给出优先级，避免八只股票逐只长篇后没有总决策：

- 趋势持仓组：结构未破，主要管理浮盈。
- 确认后观察组：等待底分型、向上离开中枢、回踩不破。
- 高位防守组：高换手、断板、顶背驰或主力兑现，只卖不买或禁止追高。

最终必须明确：

- 最值得观察的1—2只；
- 明确不应追入的标的；
- 全组共同撤销条件，例如主线梯队批量炸板或市场空间龙断板。

## 常见错误

- 默认调用AGY后再声称是主模型亲自分析。
- 只拉三字段行情就判断周一走势。
- 把KDJ/RSI超卖直接当买点，或把超买直接当卖点。
- 给固定止损价而没有说明对应的中枢、笔或背驰结构。
- 多股报告只罗列数据，不做风险收益排序。
