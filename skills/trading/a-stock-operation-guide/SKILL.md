# A股个股操作指导标准 v3 — 缠论完全分类决策

## 核心理念

❌ **不是固定价格策略**
❌ **不是零散量价条件集合**
✅ **缠论结构推演：笔→线段→中枢→背驰→买卖点的唯一分类**

**没有趋势没有背驰，没有背驰没有买卖点。**

## 分析流程（固定步骤）

### 第零步：确定复盘日期与数据边界

- 先调用交易时段接口确认当前是否交易日；若当前为非交易日，用户说"今天/昨日收盘"时，明确锁定最近一个已完成交易日。
- 历史收盘复盘必须使用该交易日的收盘字段、对应日期的 K 线和截至该收盘时点已发布的新闻；禁止混入复盘日之后的新闻、盘中缓存或"最新价"字段。
- 若实时行情接口的时间晚于复盘日，只能作为当前状态参考，不能冒充复盘日收盘证据。
- 大盘固定拉取上证、深证、创业板、科创50四指数；个股至少拉100根30分钟K线，并记录最后K线时间。

### 第零步补充：A股数据源回退策略

**Jin10 MCP（`mcp_jin10_get_quote` / `mcp_jin10_get_kline`）不支持 A 股个股代码**（仅支持 XAUUSD、EURUSD 等国际品种和指数）。分析 A 股时，按以下优先级拉数据：

| 优先级 | 数据源 | 用法 |
|--------|--------|------|
| 1 | `mcp_exec_get_positions` | 持仓股直接取 current_price（但不含 K 线） |
| 2 | 新浪行情 `hq.sinajs.cn` | 实时报价：`https://hq.sinajs.cn/list=sz300161` 或 `sh600487`（Referer: finance.sina.com.cn） |
| 3 | 新浪 K 线 `money.finance.sina.com.cn` | 历史 K 线：`https://money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData?symbol=sz300161&scale=30&ma=no&datalen=100`（scale=30 为30分钟，scale=60 为60分钟，scale=240 为日线） |

**K 线返回格式**（新浪 JSON）：
```json
{"day": "2026-08-17 14:30:00", "open": "29.880", "high": "29.940", "low": "29.870", "close": "29.920", "volume": "73500"}
```

**新浪实时行情返回格式**（GBK 编码，var 开头）：
```
var hq_str_sz300161="华中数控,30.370,昨收,开盘,最高,...,2026-08-17,14:04:12,00";
```

⚠️ 东财 API（`push2.eastmoney.com` / `push2his.eastmoney.com`）在海外 IP 下可能返回 502/连接拒绝，优先用新浪。

### 第一步：确定级别

- 短线操作：**30分钟级别**（cron 标准级别）
- 中线操作：日线级别

### 第二步：包含处理 + 分型识别

对30分钟K线做包含处理，识别**顶分型**和**底分型**。

### 第三步：画笔 + 线段

- 笔：邻接顶底分型间至少间隔1根独立K线
- 线段：由至少3笔构成

### 第四步：构建中枢

中枢 = 三个连续次级别走势类型重叠部分

```
中枢区间 = (max(低点), min(高点))
```

- 盘整 = 1个本级别中枢
- 趋势 = 2个以上同向本级别中枢（不重叠）

### 第五步：背驰判定

**标准趋势背驰（a+A+b+B+c）：**
- 比较 b 和 c 的力度（MACD黄白线/红绿柱面积）
- c 必须是次级别且包含第三类买卖点
- c 必须创新高/新低

**盘整背驰：**
- 仅一个中枢时比较中枢前后离开段力度

### 第六步：买卖点分类

| 买点 | 特征 | 操作 |
|------|------|------|
| 一买 | 下跌趋势背驰 · 至少两中枢+c背驰 | 激进买入 · 高波动 |
| 二买 | 一买后首次次级别回调低点 | 加仓 · 最安全二买 |
| 三买 | 突破原中枢+回抽不入中枢 | 加仓 · 趋势确认 |

| 卖点 | 特征 | 操作 |
|------|------|------|
| 一卖 | 上涨趋势背驰 · c段衰竭 | 清仓 |
| 二卖 | 反弹不破前高 | 减仓 |
| 三卖 | 跌破中枢+反弹不入中枢 | 清仓 |

### 第七步：区间套定位

本级别进入背驰段 → 回次级别找背驰 → 层层嵌套定位精确点

## 输出

- 收盘复盘结论先给明确动作：买入/卖出/持有/不交易；不要把“观察”写成买入信号。
- 盘中结论必须严格区分三个时间口径：`全天尚未出现买点`、`此前出现过买点但当前已错过/不可追`、`当前仍有可执行买点`。不得只根据当前价格赔率，把“现在不能追”写成“今天没有买点”；若用户追问当天是否有买点，必须回看开盘以来5分钟K线逐段复核。
- 每个动作必须标注证据日期和数据边界；如果新闻、行情或K线日期不一致，降级为“仅观察/不交易”。
- 面向用户的打法报告必须给出可直接挂单的具体买入价、加仓价、减仓价、清仓价/止损价；允许给窄幅价格区间，但不得只写“中枢、底分型、背驰、三买/三卖、均价收复”等无法直接执行的术语。内部仍可用缠论计算价格，但最终必须翻译成明确价位与动作。
- 持仓卖出前强制复核30/60分钟K线、板块共振和新闻；上升通道没有卖点时禁止仅因短期涨幅卖出。

**缠论四要素必须覆盖：**
1. 走势类型（趋势/盘整/未明）
2. 中枢位置与数量
3. 背驰状态（有/无/疑似）
4. 买卖点位置（一买/二买/三买 · 一卖/二卖/三卖）

**飞书3行格式：**
```
[emoji窗口] | 大盘XX ±X% | HOLD/操作 代码 现价 理由(背驰未现/中枢未完/一卖预警) | 无信号
```

**详细分析写入文件（~/.hermes/trading/watchlist_chanlun_YYYYMMDD.md 或 chanlun_analysis_YYYYMMDD.md）**

**盘中警戒监控集成：** 当日持仓/重点关注的个股不要新建独立 cron，应写入 `~/.hermes/trading/alert_plans/alert_plan_YYYY-MM-DD.json`，由已有的 `intraday-leader-monitor`（每5分钟 no_agent 脚本）统一扫描。格式参见 `references/alert-plan-format.md`。每5分钟自动复核缠论+基本面+新闻，触发后走LLM二审→风控→下单管道。**去重规则：同股票同方向同交易日只提醒一次**（key = `symbol:direction:plan_date`，不含价格）。尾盘恐慌抄底模式见 `a-stock-trading-orchestrator` 技能中的 `references/close-session-panic-fishing.md`。

**批量自选股扫描**：参见 `references/watchlist-batch-analysis.md`（并行子任务模式）

**多股独立分析与来源披露**：当用户明确要求由当前主模型亲自/独立分析多只股票时，必须默认禁用 AGY、披露分析来源、按最近收盘日锁定数据边界，并采用分组并行采集与统一排序。详见 `references/independent-multi-stock-analysis.md`。

**中枢计算的可审计解释**：用户追问“中枢怎么确定”或报告使用三买/三卖时，必须披露分析级别、构成三段、`ZD/ZG` 计算与回抽完成状态；区分严格“连续三个次级别走势类型重叠”和程序“三笔重叠代理中枢”，不得混称。详见 `references/chan-pivot-audit.md`。

**盘中买入价格与抄底判定**：用户明确问“买入价格/什么价买/可以抄底了吗”时，允许给条件化价格区间，但必须绑定5分钟底分型、分时均价/筹码成本收复、主力资金止血和30分钟结构未破坏；涨停后回落及次新股不得仅因跌幅或超卖抄底。详见 `references/intraday-entry-and-bottom-fishing.md`。

**涨停回踩MA50/MA60与回马枪监控**：用户询问“涨停后回踩中期均线是否洗盘”、要求多股横评，或要求“加入观察，有买点提示”时，按启动强度、回踩位置、缩量程度、成本/均线修复、资金连续性、二次突破六维分级；不得仅凭触及MA50/60断言洗盘。观察请求必须同时接入自选股与统一盘中警戒计划，并验证JSON及监控脚本。详见 `references/limitup-retest-pattern-and-alerting.md`。

**交易战法文档完整落地**：用户上传DOCX/PDF/图片版交易战法并要求“全部处理/完整落地”时，必须恢复正文与图片规则，逐战法结构化，审计幸存者偏差、未来函数、不可成交与术语错误，再用TDD实现候选扫描器、联合回归并做真实K线试跑；不得只做摘要，也不得把扫描空结果误写成脚本未运行的泛化“无买点”。详见 `references/trading-strategy-document-quantization.md`。

### 裸股票列表的默认语义与快速横评

当用户只发送多个股票名/代码（如“股票A/股票B/002565”），不要反问用途，默认解释为：**对这些标的进行实时横向比较并给出交易优先级**。

1. 先校验名称与代码映射，避免同音、简称或错码；输出必须同时写名称和代码。
2. 每票最低数据集：实时行情双源核验、100根30分钟K线、日线、主力资金、筹码、技术指标、财务、新闻；不得只按涨幅排序。
3. 统一比较维度：分时承接、30分钟中枢/买卖点、日线趋势、5/20日资金、筹码成本与获利盘、超买程度、新闻/财务风险。
4. 结论必须给唯一排序，并区分“结构优先”“强但只可二次突破”“反弹修复需确认”；禁止把三票都写成泛泛的“关注”。
5. 入场只写结构条件：回踩不入中枢、底分型、放量突破、三买确认；不得用孤立固定价格代替结构。
6. 红线统一写取消条件：距日内高点回撤过大、跌破分时均价、重新跌入中枢或形成三卖时，撤销买入计划。

### 多持仓“要不要割肉”的分级处置

用户同时报出多只持仓成本并问是否割肉时：

1. 必须用实时价计算每票浮亏比例，并复核30/60分钟结构、日线趋势、资金与新闻。
2. 将标的分为：`立即执行结构止损`、`反抽退出`、`等待结构确认`，给出明确先后顺序，不能对所有票给相同答案。
3. 已超过系统硬止损且出现三卖/资金持续流出的，结论应直接明确；但盘中处于急跌低点时，区分“现在砍”与“等反抽执行”，避免把恐慌最低点当成最佳卖点。
4. 每票同步给三件套：继续持有/加仓的结构条件、减仓或止盈条件、无条件退出条件；无加仓依据时必须明确写“禁止补仓摊成本”。
5. 若用户报出的股票此前未在持仓记录中，按 Revealed Holding Protocol 处理并更新持仓记忆。

⚠️ **用户可能要求完整报告直接输出到对话框** — 用 read_file 读取后全文发送，不要只发摘要+文件路径。

## 止损与操作区间计算

**止损禁止死套中枢下沿 × 0.97。** 必须根据股价与中枢的相对位置分段计算：

| 股价位置 | 判断条件 | 买入支撑 | 止损基准 | 目标位 |
|---------|---------|---------|---------|--------|
| 跌破中枢下沿3%+ | `price < ZD × 0.97` | 近20根K线最低点 | `recent_low × 0.97` | 中枢下沿 ZD（反弹回中枢） |
| 中枢内部 | `ZD ≤ price ≤ ZG` | 中枢下沿 ZD | `ZD × 0.97` | `ZG × 1.05` |
| 突破中枢上沿3%+ | `price > ZG × 1.03` | 中枢上沿 ZG（回踩买入） | `ZG × 0.97` | `price × 1.15` |
| 无中枢 | — | 近20根最低点 | `recent_low × 0.97` | `price × 1.08` |

**案例**：金山办公(688111) 现价240.50，中枢ZG=258 ZD=251。price < ZD × 0.97 = 243.76 → **跌破中枢**。止损不能用243.76（中枢在120块外），应该用近20根最低237.30 × 0.97 = **230.18**。同时三卖信号优先级高于底背驰+一买。

## 买卖点信号优先级

当一支股票同时出现多个缠论信号时：

```
三卖 > 一卖 > 二卖  （卖出优先级）
一买 > 二买 > 三买  （买入优先级，但注意三买是趋势确认后最强）
```

**特别注意**：一买+三卖+底背驰同时存在 → 底背驰和一买是先出现的（下跌衰竭→反弹），三卖是最新的（反弹失败→中枢向下脱离）。**三卖优先级最高，此时应减持/观望，不是买入。**

## 量价条件（嵌入缠论框架）

以下是量价条件，但**不是独立使用**，而是作为缠论三买的补充验证：

| 缠论点 | 量价验证 |
|--------|---------|
| 三买突破中枢 | 突破笔量>前日同期150%才有效 |
| 一卖c段衰竭 | c段缩量< b段50%确认衰竭 |
| 盘整突破 | 三买+板块共振放量 |
| 跌破中枢 | 三卖+放量跌破确认有效 |

## 仓位管理

- 趋势确定（三买后）：总仓8%
- 中枢构建中（趋势未明）：总仓4%
- 盘整震荡：高抛低吸，单票<4%
- 止损线：成本-6%（硬止损）+ 结构止损（中枢破坏=清仓）

## 反转/反弹/震荡判定 — 四维矩阵法

用户问"XX反转了吗"时，使用 `references/reversal-detection-four-matrix.md` 中的四维矩阵（MA排列→主力资金→K线结构→筹码成本）执行固定步骤判定。**死叉一票否决：MA5/MA10死叉+MACD水下死叉=直接❌不是反转。** 判定必须列出每条否决理由的具体数据。

## 用户报出隐藏持仓的处理（Revealed Holding Protocol）

当用户中途报出一只此前未在持仓清单或记忆中出现的股票（如"还持有XX 2000股"），处理流程：

1. **立即全维拉数**：query_data + get_fund_flow + get_technical_indicators + get_chip_distribution + fetch_kline(D/60/30三周期) + search_news，不容遗漏
2. **更新持仓记忆**：将新持仓信息写入 memory（update current positions），确保后续会话和下个 session 知道此股在仓
3. **持仓级别分析**：按 **方向判定(反转/反弹/震荡) + 三件套(加仓位/止盈位/止损位) + 板块主线归属** 输出，给出当前该股在组合中的定位
4. **反转/反弹判定锚点**：使用四维矩阵——均线排列(MA5/10/20/60/120/250) + 主力资金(5日/20日净额) + K线结构(缠论线段完成度) + 筹码成本(获利盘比例)
5. **向下的确认必须同步给出依据**：当判定"不是反转"时，列出每条否决理由的具体数据，让用户自己判断是否认可

**遇"报一个股名"（无上下文）时的分析默认深度**：拉全量数据（K线+资金+筹码+技术指标+新闻），输出6~8维度结构化分析。不做3字段浅层行情播报。

### 多持仓批量报警计划构建（2026-09-30 新增）

当用户一次性报出多只持仓（如"688798/688820/600396..."），且 broker API 返回空持仓时：

1. **批处理标准**：不逐只问用户细节，直接拉每只的 K线、筹码、资金流向，用批量数据接口一次性扫描全部
2. **alert plan 构建**：立即生成 `alert_plan_YYYY-MM-DD.json`，涵盖全部声明的标的，每只带方向=sell、sell_alert.below（基于前日最低点或筹码成本）
3. **同步更新 memory**：将新持仓写入 memory（user profile），确保后续会话和下个 session 知道
4. **告知用户限制**：说明 broker 接口未看到这些持仓，盘中防守靠 alert plan 的价格触发而非 broker 实时仓位
5. **批量 K线分析**：对每只标的拉30根日K线，快速识别 MA 排列（多头/空头/粘合）和主力资金方向，按风险等级排序输出

示例构建代码结构：
```python
plans = []
for sym, name, price, analysis in batch_results:
    stop_loss = round(prev_low, 2)  # 前日最低价
    plans.append({
        "symbol": sym, "name": name, "direction": "sell",
        "sell_alert": {"below": stop_loss, "condition": f"跌破{stop_loss:.2f}止损"},
        "thesis": f"【持仓防守】{analysis['ma_summary']}，{analysis['fund_summary']}",
        "leader_score": 55, "leader_class": "portfolio_defense",
        "catalyst_type": "holding_defense"
    })
```

## 具名战法形态核验（归海一刀等）

当用户问“某股是否符合某个具名形态/战法”时，不能凭视觉相似直接定性，必须执行**规则级审计**：

1. **先查本地正式定义/实现**：优先检索对应 skill、`scripts/` 扫描器与测试中的精确条件；报告要采用当前实际执行口径，不能用泛化口诀替代代码门槛。
2. **逐项核验而非整体印象**：至少拆成前置结构、涨幅、量能、关键价不破、板块/资金确认五项，并明确标注“通过/失败/尚未完成”。
3. **结论分三级**：
   - `严格符合`：所有硬条件已完成；
   - `形似但未确认`：价格结构相似，但当日K线未收完或触发条件尚未完成；
   - `明确不符合`：任一不可逆硬条件失败。
4. **盘中不可逆条件立即判负**：例如战法要求“缩量回调”，若当日累计成交量已超过比较日，则即使尚未收盘也已不可能重新变成缩量，必须直接判定严格形态失败；不得因价格仍守住关键位而硬解释为洗盘。
5. **形态判定与交易许可分离**：符合形态只代表进入候选，不等于立即买入；仍需实时资金、板块共振、分时承接及市场风险许可。反之，严格形态失败后若未来重新放量突破，可按新的“整理后二次突破”结构评估，不能倒改旧形态名称。
6. **输出必须给证据链**：列出形成日、推进日、回撤日的日期、收盘/最低价、成交量及量比，并给出当前可执行价位和失效价。

### “进二退一”严格核验口径

以本地正式量化实现为准：涨停后次日继续上涨达到规定幅度，随后回撤日收盘低于推进日收盘、成交量低于推进日、最低价不破涨停日收盘价。四项缺一不可。尤其注意：

- “不破涨停价”只满足价格门槛，不能替代“缩量”；
- 高位放量、超大单流出、距日内高点回撤过大时，应判为分歧/派发风险，而不是自动认定洗盘；
- 当天尚未走完但量能仍可能缩量时，只能写“待收盘确认”，不得提前盖章。

## 禁止行为

- ❌ 禁止给出固定价格 — 必须给出缠论结构的条件
- ❌ 禁止不看K线直接判断 — 必须拉100根30分钟K线
- ❌ 禁止用"形态"代替"结构" — 中枢>形态
- ❌ 禁止在无中枢未完成时预言方向 — 完全分类，等结构自己走出来
- ❌ **禁止分析持仓只给方向/只设保护位，不计算三件套（2026-08-15 教训）** — 用户追问"加仓信号、止盈信号你计算了吗"。一旦定位持仓股的缠论结构（买点/卖点位置），**必须立即同步给出三件套**：
  - 📈 加仓位：明确中枢/三买结构位（如"三买加仓位 XX"）
  - 🛑 止损位：结构破坏（如"中枢破坏位 XX"）
  - 不给"待观察/再确认"的拖延式空话；结构已走出的位置当下就报，不需要用户追问。

## 游资级别卖点执行纪律（absorbed from a-stock-selling-discipline）

> 原则：游资收割核按钮恐慌盘，不加入恐慌队伍。已决定卖出后，按以下决策树执行。

### 卖点决策树

| 竞价状态 | 操作 |
|---------|------|
| 高开 >=2% | 开盘等 5分钟 观察。竞价溢价说明有资金承接，不接恐慌第一笔核按钮；等反抽到开盘价或均价线再决策。若5分钟内持续走弱无法修复 -> 反抽分时均线出 |
| 平开或小幅低开（-1%~+1%）| 看竞价成交量，异常放量可竞价直接出；正常量则等开盘方向确认 |
| 大幅低开 >=-3% | 竞价直接出，不犹豫 |

### 禁止行为 ❌
- 竞价高开标的在开盘跳水最低位挂单出逃
- 没有给标的5分钟修复时间就急于出手
- 被散户核按钮情绪裹挟

### 校验清单（卖出前过一遍）
1. ☐ 竞价是高开还是低开？
2. ☐ 开盘跳水的幅度和成交量是否正常（竞价兑现 vs 主力出逃）？
3. ☐ 是否给了足够观察时间？
4. ☐ 这个卖点是游资级别还是散户级别？
