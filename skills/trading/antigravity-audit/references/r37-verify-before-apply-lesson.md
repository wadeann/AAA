# R37 审计教训：AGY输出代码必须经Hermes验证再落地

## 背景

2026-09-14 审计隔日起爆系统时，AGY输出三段代码补丁，其中第一段存在3个隐藏bug：
1. **UnboundLocalError**: `inflow_yi` 在 `score` 行引用但被 `yicai_data = {}` 覆盖了局部作用域
2. **dict 覆盖丢失数据**: `for item in data_list: result[item["stock"]] = item` 用key做dict，后一个覆盖前一个，丢失同key但不同逻辑的数据
3. **47分天花板 vs 60分门禁**: 评分最高50分但门禁60分——数学上永远不及格

## 教训

AGY的意图和逻辑是对的，但生成的代码文件有实现层面的bug。Hermes在应用时必须：**审读每一行修改，理解变量作用域链，检查数值边界条件。**

## 流程改进

原来流程：AGY输出代码 → Hermes粘贴 → git commit
新流程：AGY输出代码 → **Hermes审读（变量作用域/边界值/覆盖问题）** → 用patch定向替换 → 运行语法检查 → 运行测试用例 → git commit

## 检查清单

- [ ] 新引入的变量是否在所有条件分支中被正确定义？
- [ ] dict/set 操作是否会因key重复导致数据丢失？
- [ ] 评分公式的每项最大值加起来是否 ≥ 门禁阈值？
- [ ] 是否存在只在单个分支定义的变量在分支外被引用？
- [ ] AGY输出的完整文件是否有不必要的格式变更（缩进/注释/空行）？
