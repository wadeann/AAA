# AGY审计MCP数据自验证模式（2026-09-08实战）

## 核心发现

当用户质疑打印输出（如打法卡的标签"非主线高位"）的准确性时，**AGY审计不应仅审查代码逻辑，还必须自验证真实市场数据**。用户让"让AGY进行审核，告诉他怎么拉实时数据"——AGY只有拉MCP实时数据才能确认标签词语是否反映真实市场结构。

## 调用模式

在AGY审计prompt中嵌入如下结构，让AGY可以指定需要验证的数据：

```
## 审计附加要求：请自行指定需要验证的MCP数据

注意：我（Hermes）可以通过 MCP 工具拉取实时数据验证你的判断。
请在审计过程中指定需要什么数据，格式如下：

「请MCP执行：mcp_intel_query_batch_data(symbols=["xxxx.SH", "yyyy.SZ"])」
「请MCP执行：mcp_intel_get_mainline_lanes(top_n=5)」
「请MCP执行：mcp_intel_get_limitup_ladder(min_streak=1)」
```

AGY在审计报告中用这种标记声明需要的数据，Hermes会补拉供AGY复审用。

## 可用MCP数据源（AGY审计时可调用的）

### 核心验证
```
mcp_intel_query_batch_data(symbols=["605577.SH", "600540.SH"])
  → 批量实时量价（最新价、涨幅、振幅、成交额）

mcp_intel_get_mainline_lanes(top_n=5)
  → 主线赛道四维评分（攻击分/梯队分/空间/资金）+ 梯队完整性 + 龙首/跟风

mcp_intel_get_limitup_ladder(min_streak=1)
  → 全市场连板天梯（板数分布、断板龙头、2板/首板、昨日断板龙头分析）
  → 注意：board_height可能不等于effective streak（如"10天7板"）

mcp_intel_fetch_kline(symbol="605577.SH", period="D", count=20)
  → 日K线历史（确认连板事实、开盘封板/炸板回封模式）
```

### 深度分析
```
mcp_intel_fetch_market_health() — 大盘健康度
mcp_intel_get_fund_flow(symbol="600378") — 主力资金流向
mcp_intel_get_chip_distribution(symbol="600378") — 筹码分布
mcp_intel_get_technical_indicators(symbol="600378") — 技术指标
mcp_intel_fetch_sector_history(code="一带一路") — 板块历史走势
```

## 实战案例（2026-09-08）

### 质疑内容
用户说：
"龙版 国芳 集泰 新赛股份都是主线龙头啊，为什么你说是非主线高位？你眼里的主线是什么，而且万向德农断板也只是农业板块不行吧？为什么要全盘禁买？"

### AGY审计需要的核心数据
1. `get_mainline_lanes(top_n=5)` → 揭示真正的主线赛道
2. `get_limitup_ladder(min_streak=1)` → 揭示天梯图全貌（非仅看代码内的symbols）
3. `query_batch_data` 验证各标的最新涨幅

### 关键发现
| 标的 | 代码标签 | 实际数据 | 结论 |
|------|---------|---------|------|
| 龙版传媒 605577 | "非主线高位" | 一带一路83.9分+文化传媒74.5分主线龙首，6板，梯队完整 | 标签误判 — 是主线不是非主线 |
| 新赛股份 600540 | "同题材高位中位绞肉机" | 乡村振兴主线龙首，5板，农业16涨停梯队完整 | 标签措辞无误但含义易误解 — 禁买是因为5板≥5无条件锁入规则，不是它非主线 |
| 万向德农 600371 | "断板日铁律"措辞歧义 | 今天涨停（10天7板），没有断板 | 措辞歧义 — 应写"若断板"而非"断板日" |

### 根因总结
打印输出中"非主线高位"的误判有两个根因：
1. **代码层的is_primary_sec字典缺失**：primary_sectors只包含sector_matrix模块中role标记为primary_attack/secondary_attack的板块。如果文化传媒/一带一路没被标记为进攻板块，龙版就会从代码层被判"非主线"
2. **标签词与业务语义分离**：代码用"非主线高位"这个标签，但用户眼中的"主线"取决于真实的板块梯队和资金流向，不是代码里一个字典配置

## 输出标签准确度审计（标准Checklist）

当审计输出标签/措辞时，检查以下维度：

- [ ] **语义镜像测试**：输出标签的词义是否精确等于代码实际逻辑？"非主线高位" ≠ "≥5板上位锁入"
- [ ] **数据对称性**：把标签换成反向词（"主线龙首"→"非主线"），看是否与真实市场数据矛盾
- [ ] **动态标签缺陷**：标签使用 `is_primary_sec` 这类静态字典判断，但主线板块每天都在变（今天的乡村振兴可能明天退潮）
- [ ] **"禁买"vs"不可买"措辞分辨率**：禁买原因有很多（≥5板上位锁入 vs 衰竭期中位绞肉机 vs 非主线孤立 vs 边缘杂毛），每种原因的语义权重不同，不能混用

## 原则

1. **AGY审计输出措辞时，必须拉实时MCP数据验证，不能只看代码静态逻辑**
2. 标签措辞应该让用户一眼知道"禁买是因为规则X"而不是"因为代码判定它不是主线"
3. 如果代码内逻辑正确但描述词误导 → 改描述词，不改规则
4. 如果需要验证的数据量较大，AGY在审计报告中注明需要哪些MCP调用，Hermes补拉
