# 09:25 候选通知缺失：调度阻塞与负决策静默

## 典型症状

- 09:25 没收到买入候选，也没收到“非买入”通知。
- cron 列表显示任务 `last_status=ok`，但实际运行时间晚了数分钟。
- 输出文件只有 `wakeAgent=false`、`silent (empty output)`，或扫描器显示候选全部被风控拦截。

## 必查时间线

同时对照以下四项，不能只看 `last_status`：

1. cron 注册时间与 `last_run_at`。
2. cron output 文件中的真实 `Run Time`。
3. 上游长任务日志中的 sleep/阶段耗时。
4. 扫描结果、风控结果、最终注入候选数。

若 09:25/09:26 的多个独立任务都集中到 09:30+ 才运行，优先判断为调度器 head-of-line blocking，而不是所有任务同时偶发变慢。

## 根因模式一：长任务占用单线程调度器

危险模式：一个 09:24 启动的 no-agent 脚本在内部 `sleep` 到 09:29:55，期间阻塞同调度器上的 09:25、09:26 任务。

```python
# BAD：占住调度器数分钟
sleep_sec = (open_gate_time - now()).total_seconds()
time.sleep(sleep_sec)
run_open_gate()
```

修复原则：

- 早盘扫描完成后立即退出，释放调度器。
- 开盘执行交给独立的定时任务或常驻执行器。
- 不用“增大 cron timeout”解决排队；timeout 只防止误杀，不能消除阻塞。

## 根因模式二：非买入结论被静默

09:25 已完成扫描但没有可执行候选，仍然是确定性交易决策，必须送达：

```text
📊竞价09:25
📌非买入：竞价无满足条件候选；连板/真龙候选0只
✅持有 中文名(代码)
```

禁止：

- 空 stdout。
- `wakeAgent=false`。
- 仅写本地日志。
- 只有在风控前置拦截时通知，而“正常扫描得到0候选”时静默。

## 候选、批准、注入三层语义

必须明确区分：

1. **识别候选**：扫描器发现形态合格股票。
2. **风控批准**：策略熔断、黑名单、仓位等全部通过。
3. **成功注入**：写入执行队列，成为可执行买入候选。

只有第3层数量大于0，才能发送“买入候选提示”。若识别出8只但全部被策略熔断，正确消息是“非买入：8只识别候选全部被风控阻断”，不能打印“已推送买入提示”。通知应基于 `injected > 0`，而不是原始 `dragons`/`candidates` 非空。

## 旁路故障

早盘市场状态脚本即使已把状态文件写成功，也可能在最后的 CLI 格式化输出阶段因 `None` 使用浮点格式符而退出非零。所有格式化数值使用：

```python
float(data.get("median_change") or 0.0)
```

而不是：

```python
data.get("median_change", 0.0)  # 键存在但值为 None 时仍返回 None
```

## 修复验证

至少提供以下 Before / After 证据：

- Before：计划09:25，实际09:30+；After：源代码不再有跨分钟 sleep，或测试明确禁止该模式。
- Before：0候选输出为空；After：生成明确“非买入”消息。
- 单元测试覆盖：正常扫描0候选、风控阻断0注入、长等待不存在。
- `py_compile` 通过。
- 相关回归测试通过。
- 手工调用消息构造函数，检查中文名(代码)与量化原因。
