# 盘中买点漏报：静态候选池、竞价档案字段丢失与开盘累计量门槛

## 典型症状

- 个股在09:30—09:40放量突破并随后涨停，但盘中引擎连续记录 `formal_count=0 / signal_count=0`。
- 开盘狙击报告称“候选池为空”或“无买点”，事后复盘却能明确定位有效买点。
- 题材名称正确，但 `sealed_count=0`，说明引擎知道方向却没有扫描到实际强势股。

## 三层根因检查

### 1. 竞价档案是否因字段契约不一致提前退出

竞价确认产物可能只有：

```json
{"target_theme":"电力","triggered":true,"triggered_count":2}
```

而盘中脚本若强依赖 `target_score`：

```python
target_score = active_data.get("target_score", 0.0)
if target_score < 60:
    return no_signal
```

就会把已确认的竞价共振错误降为0分并在拉行情前退出。

修复原则：定义统一的有效评分函数；若档案明确 `triggered=true` 且共振数达到门槛，应继续监控，不能因可选评分字段缺失而归零。

### 2. 股票池是否仍是盘前静态名单

盘前池只代表预案，不代表盘中完整强势股。盘中每轮应：

1. 保留盘前候选；
2. 按当前有效题材实时查询涨幅、成交额和强度靠前标的；
3. 规范化代码并去重合并；
4. 对扩展后的板块池统一拉实时行情与K线。

否则开盘后新晋强势股即使产生标准突破，也永远不会被查询。

### 3. 流动性门槛是否误用全天绝对成交额

09:35的累计成交额不能使用10:00以后或全天统一阈值。例：首根5分钟成交6700万元，若全天门槛固定为8000万元，就会错误过滤真实起爆。

建议按时段设置累计成交额底线，或使用按已交易分钟投影的量比：

- 09:30—09:40：较低累计成交额门槛；
- 09:40以后：恢复常规门槛；
- 同时检查预计全天量比、突破昨高、距日内高点回撤。

## 强制排查证据

必须同时核对：

1. 竞价/盘前产物原始JSON；
2. 每5分钟运行标记中的 `theme / formal_count / sealed_count / signal_count`；
3. 当时的5分钟K线与累计成交额；
4. 股票是否实际存在于引擎本轮 `symbols`；
5. 脚本是否在行情调用前提前 `return`。

## Before / After 验证

修复不能只看单元测试，至少提供：

- **Before**：目标题材正确，但连续多轮 `sealed_count=0 / signal_count=0`；
- **After**：同一真实盘面运行时，动态池能识别新增涨停/强势股；
- 回归测试覆盖“盘前池缺少盘中新晋股”“竞价档案缺评分但已触发”“开盘前10分钟累计成交额门槛”；
- `py_compile`和相关测试集通过。

## 报告口径

必须区分：

- **全天没有出现买点**；
- **当前时点已经没有可追买点**；
- **系统漏报了此前已经出现的买点**。

不得把“当前不能追”改写成“今天没有买点”。
