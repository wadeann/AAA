# 策略前瞻运行验收协议

用于“从明日开始记录，运行一段时间后复核”类任务。目标是评价策略在真实时间顺序下的发现、执行和收益能力，避免只保留成功案例或用回测替代实盘证据。

## 1. 启动时必须完成

1. 固定策略名称、版本、起始日期和基线指标。
2. 确认盘中策略入口已经启用，并能写机器可读台账。
3. 增加 `strategy_run_marker`：每次运行都记录，包括零候选、零信号和被风控拦截的轮次。
4. 验证影子候选、正式候选、订单、成交和结果之间有稳定 ID 可关联。
5. 建立到期验收任务；任务提示必须自包含数据路径、统计口径、基线和输出要求。
6. 用自动化测试证明“零信号也落盘”，不能只验证有候选的成功路径。

## 2. 推荐记录类型

### strategy_run_marker

至少包含：

- `strategy_version`
- `date`、`time`、`mode`
- `catalyst_type`
- 输入市场/板块摘要
- `formal_count`、`shadow_count`、`signal_count`
- `result: signal | no_signal | blocked | error`
- 过滤或阻断原因

### shadow_candidate / candidate

必须保留当时已知的入场价、买入上限、止损、目标、板块证据、量价证据、时间戳及失效条件。事后不得改写为更理想的价格。

### candidate_event

记录审核、风控、报单、拒绝、提交失败、成交回查等每个断点。`submitted` 不等于成交；成交必须有订单号、成交价和数量。

### shadow_outcome / candidate_outcome

至少包含：收盘/退出收益、MFE、MAE、止损与目标谁先触发、持有期、退出原因。影子结果不得混入真实收益。

## 3. 到期验收指标

必须同时报告：

- 计划运行次数、实际运行次数、缺失轮次、零信号率；
- 影子候选、正式候选、风控通过、报单、成交数量；
- 候选→成交转化率及各阶段断点分布；
- 影子胜率与真实成交胜率；
- 平均/中位收益、平均 MFE/MAE、盈亏比、止损率、目标达成率；
- 真实已实现收益，单独列示研究成功但未成交的机会；
- 与启动时历史基线的 Before/After 对比；
- 样本量和置信限制。

没有真实成交时，结论只能是“发现层表现”，实际收益为 0；不能用后续涨幅模拟成已赚利润。

## 4. 验收决策

- 样本不足：继续观察，不提高仓位，不宣称高胜率。
- 发现有效但转化率低：优先修执行闭环和价格计划，不急于改选股规则。
- 正式样本显著弱于影子样本：检查审核、风控、时延和排名器是否反向筛选。
- MFE良好但实现收益差：优化退出规则，而不是继续收紧入场。
- MAE/止损率恶化：先降仓、提高门槛或暂停新增风险。
- 只有在前瞻样本覆盖正负案例、执行证据完整且风险指标可接受时，才允许固化或提高优先级。

## 5. 审计红线

- 不删除零信号日和失败记录。
- 不以后见之明修改入场、止损、目标。
- 不把 Cron `last_status=ok` 当作业务运行成功；必须检查落盘记录。
- 不把影子收益、未成交机会或报单未回查记录计入真实盈利。
- 到期任务必须读取原始 JSONL 与真实成交/订单，不只读取摘要报告。
