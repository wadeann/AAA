# AGY编码R1审计：auction_kill_switch.py 竞价核按钮（2026-09-07）

> **审计评分：42/100** — AGY以游资股神身份审计，发现3个P0、5个P1、2个P2缺陷
> 
> 核心教训：AGY编出的代码虽然语法正确逻辑通顺，但缺乏盘口博弈的微观机理认知，存在严重实战盲区

## P0 致命缺陷（必须在AGY prompt中预防或在写代码后手动修复）

### 1. 【炸板一刀切】误杀弱转强大肉

**现象**：`kill_cond3 = yesterday_bombed` — 昨天只要是炸板，今天无论高开多少都强平。平潭发展竞价+5.1%浮盈+11.79%因昨日炸板被强平。

**正确逻辑**：
- 昨日炸板 + 今日低开 < -1.0% → 核按钮
- 昨日炸板 + 今日平开/高开/爆量 → 弱转强观察，禁止强平

**给AGY的prompt要写入**：昨日炸板不等于今日必卖，炸板标的按今日竞价涨跌分叉处理。

### 2. 【常态误杀】微幅低开+正常缩量被强平

**现象**：`kill_cond2 = (current_price < prev_close) and (auction_vol < yesterday_vol * 0.005)` — A股90%的票竞价量只有昨日的0.1%~0.4%，微跌-0.2%直接被秒杀。

**正确阈值**：只有 `open_pct < -1.5%` **且** `auction_vol < yesterday_vol * 0.002` 才算弱势承接坍塌。常态低开(-1.5%~0)属于分时消化区间。

### 3. 【执行阻断】price=-1 导致exec_server拒单

**现象**：传 `price=-1` 代表"市价"，但底层 exec_server 检查 `price < limit_down` 时看到 -1.0 直接拒绝。

**正确做法**：核按钮必须计算合规跌停价：`limit_down_price = round(prev_close * (1.0 - limit_ratio), 2)`

## P1 严重隐患

### 4. 【涨停价算错】代码前缀匹配失效 + 银行家舍入

**问题**：`startswith(("300","301","688"))` — 传入`SZ300059`时匹配失败回退10%。Python `round()`是偶数舍入非标准四舍五入。

**修正**：纯数字提取 `code_digits = "".join(c for c in symbol if c.isdigit())[:6]`，涨停用 `math.floor(x*100+0.5)/100`。

### 5. 【锁仓骗炮】高开+1.5%+爆量无法抵御诱多出货

**问题**：主力9:24:50顶虚假买单制造高开，9:30砸盘。1%昨量对缩量一字板太小。

**修正**：锁仓必须结合绝对金额（竞价成交额>1500万）或竞价换手率>1%。高连板要求 `open_pct >= +2.0%`。

### 6. 【竞价量为0地雷】9:25数据源延迟触发误杀

**问题**：9:25撮合完成后1-5秒内行情volume仍为0，auction_vol==0 + 微跌 → 误判强平。

**修正**：`if auction_vol == 0: continue`（数据未就绪直接跳过）

### 7. 【性能死锁】串行MCP调用耗尽9:25-9:30黄金5分钟

**问题**：循环串行query_data+fetch_kline，5只持仓最差80秒。

**修正**：用 `query_batch_data` 批量获取。单次MCP超时压至2.5秒。

### 8. 【时序守卫缺失】缺少时间窗口校验

**问题**：脚本没校验是否在09:25-09:29执行，非交易日也会触发。

**修正**：入口加 `is_trading_day` + 09:25:05~09:29:50窗口锁。
