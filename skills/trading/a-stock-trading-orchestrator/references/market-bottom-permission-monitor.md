# 大盘抄底许可监控合约

## 适用场景

用户要求“等大盘可以抄底时告诉我”时，不能只口头承诺，也不能用单一指数跌幅主观判断。应建立确定性、可审计、仅在状态切换时提醒的盘中监控。

## 监控模式

- 使用 `no_agent` 定时脚本，交易日盘中每 5 分钟运行。
- 非交易日、非连续竞价时段、接口字段缺失或数据不新鲜时静默退出并 fail closed。
- 无触发时 stdout 必须为空，避免飞书重复噪声。
- 保存当日状态；只在 `不可抄底 -> 可试仓` 的首次跃迁时发送一次提醒。状态继续为可抄底时不得重复推送。
- 新交易日重新开始状态判定。

## 许可条件

抄底许可必须由市场状态、广度、情绪和流动性共同确认。建议最低门槛：

1. 市场状态机数据新鲜，`fail_closed=false`，且不处于 `sell_only_mode`。
2. `standard_regime` 已脱离 `freezing/panic_ebb`，进入 `diverging/emerging/accelerating`。
3. 创业板涨跌幅不低于 `-0.50%`。
4. 全 A 涨跌幅中位数不低于 `0%`。
5. 炸板率不高于 `35%`；字段缺失不得按 0 处理。
6. 跌停家数不高于 `10`，涨停家数不少于 `20`。
7. 市场健康分不低于 `45`。

任一条件不满足即保持禁止抄底。阈值应由生产参数或回测管理，不要在多个脚本中产生互相矛盾的副本。

## 通知格式

触发消息必须直接可执行，最多三行：

1. `🟢【大盘抄底许可已打开】恐慌熔断解除，可先试仓20%，不一次满仓。`
2. 同屏列出创业板、全 A 中位数、炸板率、涨停/跌停家数、市场健康分。
3. 说明允许的方向及撤销条件：只做低位首板/1进2强承接；若创业板再破阈值、全 A 中位数翻绿或炸板率重新越线，立即撤销许可。

## 风控语义

- “许可打开”只代表允许开始筛选和小仓试错，不等于任何股票自动满足买点。
- 首次总仓建议不超过 20%；具体股票仍必须经过实时行情、K线、板块、新闻、资金、风险审批和执行闭环。
- 极寒日的单次急拉、单一指数翻红或健康分孤立改善，均不足以触发许可。
- 条件恶化后应立即恢复禁止开仓；如需再次提醒，必须先观察到许可关闭，再发生新的有效跃迁。

## 验收

1. 语法检查通过。
2. 用合成数据验证一组 `ready=true` 和一组 `ready=false`。
3. 真实盘中阻断态运行应退出码为 0 且 stdout 为空。
4. cron 状态必须为 enabled/scheduled，并有合法 `next_run_at`。
5. 人工模拟连续两次 ready，确认只有第一次输出提醒。
