# 盘前打法指令卡生成管道

## 管道概述

用户触发「今日打法」/「输出今日打法」时，必须执行 `python3 ~/.hermes/scripts/print_playbook.py`。

该脚本调用链：
```
print_playbook.py
  → compile_plan(today)         # ~/.hermes/scripts/premarket_plan_compiler.py
    → load_ladder(today)        # 读取 trading/data/ladder_YYYY-MM-DD.json
    → load_sector_kinetics()    # 板块资金流 + daily_limitup 成交额
    → classify_sector_role()    # primary_attack / secondary_attack / defensive_exit
    → assess_sector_momentum()  # 0-100 动量评分
  → generate_tactical_playbook(plan, params)
    → 实时炸板校验（2026-09-03 新增）
    → 按板块优先级生成 ≤3 条进攻/防守打法
    → 持仓防守策略
    → 红线绑定
```

## 关键陷阱：静态连板天梯 ≠ 今日实际走势

### 问题根因（2026-09-03 实战教训）

`load_ladder()` 从 `trading/data/ladder_YYYY-MM-DD.json` 读取连板天梯。该文件由收盘复盘 cron（`limitup-watchlist-close`, 15:25 CST）生成，反映**截至昨天收盘**的连板数据。

盘后出明日打法时，如果直接套用天梯中的连板梯队而不做实时校验，会产生致命错误：
- **昨天2板的票，今天可能已3板炸板**（如九牧王 601566，9/3 从 11.40 炸到 10.05 翻绿边缘）
- **炸板票仍然出现在"2进3"进攻名单中**，用户看到后信任并执行 → 炸板次日接飞刀

### 修复方案（R36, 2026-09-03）

在 `generate_tactical_playbook()` 函数中（`premarket_plan_compiler.py` 第670行附近），打法生成**之前**新增实时炸板校验模块：

1. **批量拉取 MCP 30分钟K线**：对所有攻击板块候选标的调用 `mcp_intel_fetch_kline(period="30", count=30)`
2. **炸板判定双标准**：
   - 标准1：日内最高触及涨停价（≥prev_close×1.097）且收盘较最高点回撤≥5%
   - 标准2：任意30分钟K线振幅≥8% 且触及涨停价
3. **炸板板块自动降级**：身位龙炸板 → 整个板块的输出从 `"X进Y与容量中军: 仅做竞价..."` 变为 `"⚠️ 已炸板降级: 只做持仓减仓防守，不开新仓"`
4. **炸板票自动加入防守清单**：即使该板块有持仓，也不再输出买入指令

### 验证方式

修复后重新运行 `python3 ~/.hermes/scripts/print_playbook.py`，输出中的消费零售板块应显示为炸板降级，九牧王不再出现在进攻名单中。

### 脚本位置

- `~/.hermes/scripts/print_playbook.py` — 入口，终端 + cron 双用
- `~/.hermes/scripts/premarket_plan_compiler.py` — 核心编译器，含四层预案 + 炸板检测

## 盘后分析的工作流铁律

当用户在盘后（15:30后）要求分析或出打法时：

1. **不能用静态天梯直接输出** — 天梯反映的是昨天收盘状态
2. **必须先拉 MCP 实时数据**（`query_batch_data` + `fetch_kline` 30分钟）验证今天的实际走势
3. **炸板、冲高回落、天地板的票必须自动剔除出进攻名单**
4. **空信号是合法输出** — 不要为了"有事做"而造信号

## 与 cron 的关系

`print_playbook.py` 不通过 cron 定时触发。它是用户手动触发的交互指令。但盘中 cron（如 09:25 盘前扫描、09:40 开盘狙击）各自独立运行，它们的扫描逻辑不依赖 playbook 输出。

## 龙头分阶段框架（2026-09-08 用户纠正 + AGY股神确认）

**核心教训**：原预制的"≥3板不看，只看低位补涨"被用户和AGY股神纠正为典型丢大肉姿势。

### AGY股神（30年游资）评价
> "龙头真正的黄金买点是1进2和2进3（确认分歧转一致那一刻）。首板太模糊，4板后没舒服上车位了。
> 分段没问题，但补涨龙不是在龙头断板那一刻才找——3板强化时就得开始挖。你断板那天补涨龙已经2板了，才反应过来？黄花菜都凉了。
> 原Agent做法错失大肉。
> 实战最聪明的是在1进2上车，3板确认后分仓挖掘补涨，到了7板+你手里已经拿着补涨种子了，不是纠结高位要不要接。
> 框架可用，但实战得灵活——补涨应该是跟龙头同步发育的副线仓位，不是后手。"

### 打法卡生成时对龙头位置的自适应

| 龙头当前板数 | 打法卡第1条 | 打法卡第2条 | 操作纪律 |
|:-----------|:----------|:----------|:--------|
| 1~2板 | 分歧转一致买点信号 | 同题材首板备选 | 核心买点，可满仓 |
| 3板 | 锁仓+加仓条件 | 同步挖补涨种子 | 补涨该有1板了 |
| 4~6板 | 持仓运营提醒 | 补涨确认加仓 | 加速不追，不得新开 |
| 7板+ | 断板预警+切换方向 | 补涨龙调仓 | 高位绝对不追，切补涨 |
| 断板/混沌 | 新题材首板方向 | 防守观望 | 首板砍仓试错≤5% |

**关键校验**：`generate_tactical_playbook()` 在输出打法前，先通过 `market_dragon.streak` 识别龙头当前阶段，按上表选择对应的打法卡模板。不得对所有阶段输出相同模板。
