# 真正买入触发判定契约

## 目的
回答“什么情况会真正触发买入”“为什么有候选却没下单”时，必须区分研究信号、影子跟踪、可执行候选和真实委托，禁止把影子收益或复盘评级说成交易。

## 四级状态

1. **观察/影子层**
   - `record_type=shadow_candidate`、A/B/C浪评级、MFE/MAE、`shadow_outcome` 都只是虚拟跟踪。
   - 即使 `llm_approved=true` 或 `agy_approved=true`，也不等于满足实盘证据，更不等于已委托。

2. **研究证据层**
   买入候选至少必须具备：
   - 当日实时行情确认 `realtime_confirmed=true`
   - 量价确认 `volume_confirmed=true`
   - 板块共振 `sector_confirmed=true`
   - 基本面核实 `fundamental_confirmed=true`
   - 新闻/公告核实 `news_confirmed=true`
   - 对常规结构策略，还需有效买点与结构确认；突破/竞价策略按各自路由补充突破或竞价证据。

   任一关键证据缺失时，应明确报告具体缺项，不要只输出笼统的 `research evidence gate incomplete`。

3. **市场与风控层**
   - 全局熔断只在宽基、跌停数、炸板率等系统性条件触发。
   - 单一窄基下跌只隔离对应市场。例如科创50孤立下跌时，阻断科创板买单，不能冻结主板、创业板和北交所。
   - 同时检查策略冷却、隔离板块、交易时段、追高/跌停、T+1、持仓数量、总仓比例、现金与100股整数单位。
   - 情绪系数只缩减仓位，不应被描述成“信号消失”；最终下单仓位 = 原计划仓位 × 情绪系数，并继续受总仓和现金上限约束。

4. **真实执行层**
   只有完整出现以下证据，才可称为“真正触发买入”或“已下单”：
   - 风控审批通过；
   - 有效 `intent_id` 注册成功；
   - `place_order` 返回非空 `order_id`；
   - 按该 `order_id` 回查到委托状态；
   - 写入审计归档并发送交易通知。

   没有 `order_id` 时只能说“候选通过到某一层”或“准备下单失败/被阻断”，不得说成交或触发买入。

## 排查顺序

当用户追问为什么没买，按以下顺序定位第一个断点：

1. 当日 JSONL 是否存在正式 `candidate`，还是只有 `shadow_candidate`；
2. 审核状态是否为批准，是否仍在 `awaiting_llm_review`；
3. 五类研究证据具体缺哪一项；
4. 分市场/分板块门禁是否只阻断了对应范围；
5. 策略冷却、情绪系数及总仓限制；
6. risk decision 与 `exec_registered`；
7. `order_id` 和订单回查结果。

## 用户可见回答模板

```markdown
结论：当前是【影子观察 / 正式候选 / 风控通过 / 已委托】中的哪一级。

未买入的第一断点：<具体字段或门禁>。
解除条件：<可实时验证的条件>。
真正成交标准：intent注册成功 + order_id + 委托回查。
```

回答应优先说“当前卡在哪一层”，再列触发条件；不要先堆叠全部架构术语。
