# Cron 飞书输出格式规范

## 核心原则

飞书消息在手机上 3 秒扫读。格式目标：**第一眼就知道该不该操作**。

**适用范围：所有交易相关输出** — 本规范不限于 cron，对话回复、观察池复核、alert plan 摘录等一切给用户看的分析输出同样适用。用户明确不满只看代码（"代码要转换成股票名称，不然不好看懂"）——任何分析输出必须带中文名，禁止只输出 `300503.SZ` 这种裸代码。

## 统一模板

### 第一行：标题栏（必须）
```
📊{窗口名} | 上证XXXX {sign}X.XX% 深成{sign}X.XX% 创指{sign}X.XX% 科创{sign}X.XX% | 今日盈亏≈{sign}X.XX元
```

### 操作区（按优先级排列，有才算，没有不写）
```
🔴卖出 {中文名}({代码}) 现价{价格} → 提交{数量}股
　原因：缠论简短理由（≤20字）

🟢买入 {中文名}({代码}) 现价{价格} → 提交{数量}股
　原因：缠论简短理由（≤20字）

⚠️减仓 {中文名}({代码}) 现价{价格}
　原因：缠论简短理由（≤20字）

✅持有 {中文名}({代码}) 现价{价格} {sign}X.XX%
　状态：简短理由（≤15字）
```

### 风险区（可选）
```
⚠️风险提示
　{中文名}({代码}) 风险类型：简短原因
```

### 空信号
```
📌无信号
　{简短说明}
```

### 09:25 非买入/风控阻断（必须送达，禁止静默）
```
📊竞价09:25
📌非买入：{明确量化原因}
✅持有 {中文名}({代码})、{中文名}({代码})
```

09:25 已完成决策但结论为“不买”时，属于需要送达的交易指令，不属于可静默的普通空信号。持仓已满、情绪熔断、只卖不买、风控阻断、**正常扫描后0候选、识别候选全部被策略熔断/黑名单拦截**等情况必须明确发送原因；`wakeAgent=false`、空 stdout 或仅写本地日志均不合格。

候选通知的口径必须分层：
- 识别候选数：扫描器形态命中数；
- 风控批准数：通过策略熔断、黑名单、仓位门禁的数量；
- 成功注入数：真正进入执行队列的数量。

只有成功注入数大于0，才允许使用“买入候选/已推送买入提示”。若识别出标的但最终注入0笔，必须输出“非买入：N只识别候选全部被风控阻断”，严禁用原始名单生成误导性买入提示。

## 格式铁律

1. **中文名(代码)** — 必须同时出现，如 紫金矿业(601899)
2. **每只股票独立一行** — 绝对不用 `|` 把多只股票挤在同一行
3. **缩进用全角空格 `　`** — 原因/理由行缩进
4. **Emoji 前置** — 🔴卖出 🟢买入 ⚠️减仓 ✅持有 ❌不碰
5. **价格是实际现价** — 从 MCP 查到的，不编造
6. **不出大盘分析/板块分析/浪型判定/情绪描述** — 那些写文件
7. **空块写"· 无"** — 保持结构完整
8. **总数≤8行** — 超过就精简
9. **手动补输出也严格遵守** — 当 cron 漏跑导致 agent 在对话中手动输出时，必须同样遵守本规范（用户看的还是飞书消息，不是文件）
10. **盘中推送遵循"例外警报"(Alert-on-Exception)原则（2026-09-25新增）** — 盘中监控脚本（如 intraday_theme_trigger、盘中起爆点引擎、龙头监控等）仅在检测到触发信号（买入候选/卖出触发/熔断/持仓跌破防守线/仓位达到硬上限）时才推送到飞书。**严禁**将"未触发/共振不足/无候选/守护进程正常/当前持仓安全"等阴性或心跳状态频繁推送——这属于典型的信息噪音与警报疲劳。特别禁止固定时点发送“14:00巡检报平安”：安全巡检逻辑必须继续运行，但消息层保持静默；阴性状态仅在关键决策节点（09:25竞价定调、11:30午盘总结、15:00收盘复盘）汇总报告。
11. **删除消息不等于删除风控** — 用户要求删除“安全巡检”时，先区分后台检查与飞书通知：保留高频止损、移动止盈、撤单和异常检测，只移除无动作的例行心跳。修改后必须验证异常分支仍能通知、正常分支不通知。

12. **条件预案的执行状态必须真实** — 输出具名触发价时，必须标明它处于哪一层：`仅供观察`、`已注册持续跟踪`、`触发但被风控阻断`、`已提交委托(order_id)`、`已成交`。只有后台已存在当日结构化计划、守护进程会持续加载、触发后会重新拉实时市场数据并走 risk→exec→订单回查，才能写“系统持续跟踪/满足后自动报单”。禁止把纯文字预案说成自动交易，也禁止把 PENDING/已报说成已成交。

13. **候选池刷新口径必须量化** — 用户询问“会不会持续更新候选”时，不得只回答架构设想。必须核验并报告：盘后全市场扫描时间、盘中刷新时间、高频触发频率，以及最近一次真实运行的 `扫描范围/形态命中/有效候选/成功注入` 四个数字。若当前只有单票扫描器、没有候选生命周期或没有警戒计划接入，应明确说“尚未持续跟踪”，并先完成接入和验证后再改口。

## 标签措辞准确度铁律（2026-09-08 新增）

**教训**：用户会戳穿任何语义不准确的标签词。

| 错误示例 | 用户反应 | 正确操作 |
|---------|---------|---------|
| 把龙版传媒标为"非主线高位" | 龙版是一带一路+文化传媒双主线龙首，为什么是非主线？ | 先拉 get_mainline_lanes() 确认真实主线赛道，用"≥5板上位锁入"等规则语义标签 |
| 把万向德农说成"断板日" | 它今天涨停了，为什么说它断板？ | 先拉 query_data 看实时涨幅，确认到底是连板还是断板 |
| "退潮空仓防守"过于绝对 | 农业板块还有很多首板涨停，为什么全盘禁买？ | 精准表述：先说禁某类（同题材≥3板中位股），再说可买方向（首板补涨） |

**规则**：
1. **标签词必须经过MCP数据验证后再输出** — 不能只看代码内部字典判定就说"非主线"
2. **标签词必须精确反映规则语义** — "≥5板上位锁入"比"非主线高位"准100倍
3. **禁买必须带原因分类** — 是"≥5板上限熔断"、"同题材高位中位绞肉机"还是"孤龙无梯队"？每个原因权重不同，不能混用
4. **不输出未经MCP确认的状态断言** — 不确定某个标的是连板还是断板？先查实时数据再决定措辞

## 实战打法卡极简3行格式（2026-09-08 AGY游资审计后修复）

**核心原则**：用户要的是每日最强荐股（具体标的+价格区间），不是风控规则长篇大论。

```text
🎯【Antigravity 盘后次日实战预案卡 (T+1) | 备战 NNNN-MM-DD】
──────────────────────────────────────────────
打法(≤3 条，具名):
1.【主攻空间】百大集团(600865) 14.01~14.70分歧低吸/打板|止损13.12|目标17.86|仓位25% (大消费4进5总龙)
2.【次强先锋】亚盛集团(600108) 5.39~5.65弱转强打板|止损5.04|目标6.60|仓位20%；备选:读者传媒(603999) 7.36~7.58低吸|仓位20%
3.【持仓&风控】平潭发展(7.90)破7.66止盈，冲8.29减半；线上线下(94.69)破91.69止损；集泰股份若核按钮或断板，全盘禁追老题材高位
```

**严禁**：
- 输出600+字的风控规则长篇（AGY判定为\"无效系统\"）
- 衰竭期(exhaustion)直接躺平写\"只卖不买\"而没给出新进攻方向荐股
- 只写板块名称不写股票代码（如\"大消费\"、\"农业粮食\"）

### 荐股引擎选股逻辑

由 `select_actionable_recommendations()` 函数在 `premarket_plan_compiler.py` 中运行，遵循：

1. **剔除衰竭期总龙本身**（如集泰股份6板不推买入）
2. **第1位：主攻空间** — 主线（primary_attack/secodary_attack）中最高板（3~5板标的），给25%仓位
3. **第2位：次强先锋** — 另一主线中次高板，给20%仓位
4. **第3位：低位起爆** — 主线中1进2或2进3容量标的，给20%仓位
5. 价格区间严格按当前价×1.02~1.07计算买入区间、×0.955止损、×1.18~1.30目标
6. **即使大盘处于exhaustion阶段也必须有荐股输出** — 因为新主线总龙与老总龙是不同题材

### 问财字段名陷阱

问财 API 返回的字段名**不是**标准的 `最新价` / `收盘价` / `所属行业`，而是包含日期后缀或不同命名约定：

| 你以为的字段名 | 实际返回的字段名 |
|:---|:---|
| `最新价` | `收盘价[20260908]`（含日期后缀）→ 必须遍历key匹配`"收盘价"`或`"最新价"` |
| `所属行业` | 概念类关键词如\"西部大开发\"/\"糖业\"在问财中属于**所属概念**，不是所属行业 → 必须用`所属概念包含{name}`或`所属同花顺行业包含{name}` |
| `涨跌幅` | `最新涨跌幅` 或 `涨跌幅`（有时也有日期后缀） |

**2026-09-08教训**：`intraday_hot_sector_sniper.py` 用`所属行业为{sec_cond}`查\"西部大开发\"得到0条结果，因为西部大开发是概念不是行业。修复为双条件扫描后正常抓出糖业涨停股（红棉股份/中粮科技/保龄宝）。

**代码修复模式**：问财字段遍历时不能用 `d.get("最新价", 0)` 这种固定key写法，必须用：
```python
for k, v in d.items():
    if v is not None and any(x in k for x in ["收盘价", "最新价"]):
        try: price = float(v); break
        except: continue
```

## 收盘复盘工作流（absorbed from `evening-replay`）

### 触发条件

每日收盘后（15:10 CST）触发。由 `收盘复盘+明日预案` cron job 加载本 skill。

### 两阶段流程

**阶段一：取数（一次性拉齐）**

1. **四大指数收盘**：`mcp_intel_query_data` 上证000001.SH/深成399001.SZ/创指399006.SZ/科创000688.SH
2. **持仓**：`mcp_exec_get_positions` + `mcp_risk_daily_pnl`
3. **成交**：`mcp_exec_get_today_trades`
4. **板块资金**：wencai + fetch_sector_history
5. **市场情绪**：fetch_hot_signals + fetch_market_health（仅做交叉参考，不依赖）
6. **持仓K线**：每只持仓 `mcp_intel_fetch_kline(period="30", count=100)`
7. **新闻**：每只持仓 `mcp_intel_search_news` + jin10快讯

**阶段二：写作**

- **完整报告** → `~/.hermes/trading/reviews/review_YYYY-MM-DD.md`
- **飞书输出** → ≤3行（严格按上方格式规范）

### 复盘飞书输出铁律

1. **≤3行**。大盘+账户1行，操作1行（如有），次日方向1行
2. **禁止**使用 `🎯📈📉🛑` 固定点位标记 — 价格是缠论结构的计算结果
3. **禁止**大盘分析、板块分析、浪型判定、情绪描述
4. **空信号**："无信号" / "空仓无事" / 合计不超过50字
5. 完整报告写入 `reviews/review_YYYY-MM-DD.md`，不在飞书推送路径

### 复盘数据优先级

1. MCP 获取的实时数据 — 第一优先级
2. MCP 无法获取的（涨跌家数/涨停统计/龙虎榜/北向资金） → 标⬜，不编造
3. 跨市场联动（港股/美股/期货） → 标⬜，注明"需外部数据源"
4. 禁止用历史数据假装当日数据

### 复盘简化原则

用户的复盘模板（53段/66表/2.6万字）远超MCP数据能力范围。采用精简版：
- MCP能拿到的 → 填实
